# 백준·기업 코딩테스트 학습 노트

## 구성

기존 2024년 상반기 백준 문제 글 10편과 GitHub 정리 안내 1편을 재작성했다. 추가 백준은 기존 문제 번호와 겹치지 않는 100편이며 실버·골드권 연습 대상으로 골랐다. 날짜는 2024-01-01~06-30의 학습 순서로 재구성했다. 문제별 설명·풀이 순서·정당성·Java 11 전체 코드·자체 입력·기대 출력·복잡도·주의점을 담았다.

기업 대비는 백준 100개에 포함하지 않는 별도 36편이다. 공식 프로그래머스 고득점 Kit 32개와 공식 원문에 카카오 출제 분류가 있는 4개를 사용한다. 유형 단위의 공식 빈도 표기와 개별 문제 출제 빈도를 구분했다. 기업별 출제 횟수나 비공개 기출을 만들지 않았다. 원문 36개를 2026-10-16에 확인했고 당시 규칙에 맞춰 게시 날짜도 그날로 두었다. 디스크 컨트롤러의 2024-11-14 지문 개정과 작업 동률 기준을 반영했다.

## 원문·난도·검증의 한계

확인 당시 BOJ 공식 홈페이지는 채점 준비 안내를 표시하고 문제 주소는 404였다. solved.ac API는 403으로 현재 등급을 검증할 수 없었다. 번호와 원래 주소를 보존하고 문제 전체를 복제하지 않으며 세부 등급을 현재 검증한 목록으로 표현하지 않는다. 자체 예제를 컴파일·실행했으며 온라인 정답·시간 제한 통과 기록으로 표시하지 않았다.

## 기존 파일과 주소 보존

기존 67개 삭제 상태를 복구하거나 스테이징하지 않았다. 정리 대상 11편은 새 `_posts/Coding2024/Existing/` 파일로 작성하고 원래 permalink를 명시했다. 원래 파일은 `_config.yml`에서 개별 제외해 CI 체크아웃에서 두 게시글이 같은 URL을 생성하지 않게 했다. 나머지 기존 파일과 청첩장은 유지한다.

## 검증

Java 코드 226개(웹 개발 80, 백준 110, 기업 대비 36)를 Prettier 3.6.2 + prettier-plugin-java 2.7.6으로 줄바꿈·들여쓰기를 정리했다. 도구는 gitignored 경로에만 설치했고 프로젝트 의존성을 바꾸지 않았다. 정돈 후 실제 게시 Markdown에서 다시 코드를 추출해 검증했다.

- 백준 110개: 자체 입력·출력 233회 대조.
- 기업 대비 36개: main의 출력 36회 대조, 내부 함수 호출 예제 73개 포함.
- 합계 146개 코딩 풀이 컴파일, 출력 대조 269회 통과.
- Java 40개 콘솔 출력과 Spring JUnit 40개도 서식 변경 후 재검증 통과.

```bash
python3 scripts/validate-coding-notes.py
python3 scripts/validate-java-spring-notes.py
npm test
```

배포 워크플로에서도 Java 11로 같은 원문 코드를 검사한다. 사이트 검사는 두 목차와 게시판 노출, 원래 URL, 코드 보존, 공식 링크, 로컬 탐색 링크, 공통 UI를 확인한다. 파일별 목록과 테스트 입력은 `CODING_2024_MANIFEST.json`, `COMPANY_CODING_MANIFEST.json`에 있다. 출처 HTTP 확인은 `COMPANY_CODING_SOURCES.json`에 기록한다.
