## 빌드와 콘텐츠 검사

- 작업 폴더의 전체 Jekyll 빌드와 Node 사이트 검사 40개 통과.
- 커밋 `af519a5`를 별도 체크아웃해 원격에 있는 기존 파일까지 포함한 배포 소스를 빌드했다. 기존 삭제 상태에 의존하지 않고 일반 글 1,103편의 생성 문서·자산·내부 탐색 등을 확인했다.
- Windows의 CRLF 체크아웃에서 발생한 개념·코드 추출 검사 오류를 고쳤다. 줄바꿈만 LF로 정규화하며 코드 내용 대조는 유지한다. 수정한 검사로 별도 체크아웃의 40개 사이트 검사가 모두 통과했다.
- 앞선 실행 검증: Java 콘솔 40개와 Spring JUnit 40개, 코딩 풀이 146개 컴파일·기대 출력 비교 269회, C# 48개 컴파일·출력 비교. Python·자격증·지방세의 검사 범위는 각 기록에 남겼다. 변경하지 않은 예제에 대해 같은 검사를 불필요하게 반복하지 않았다.
- GitHub Actions는 빌드·사이트 검사와 Python/Pi·지방세·C#·Java/Spring·코딩·자격증 실행 검사를 수행한 뒤에만 Pages 산출물을 배포한다.

## 실제 브라우저 화면

설치된 Chrome을 별도의 헤드리스 테스트 프로세스로 실행했다. 사용자 브라우저의 설정이나 확장 프로그램을 변경하지 않았다.

- 일반 글 1,103편과 목차·목록 11개를 320px·390px·1440px에서 확인했다. 총 3,342개 렌더링에서 페이지 가로 넘침·본문 영역 이탈·공통 문서 틀 누락이 없었다.
- 작업 폴더의 일반 글 1,053편과 목차·목록은 실행 중인 로컬 서버로, 로컬에서 이미 삭제된 기존 50편은 별도 체크아웃에서 생성한 HTML과 같은 로컬 자산으로 확인했다. 삭제 파일을 원래 작업 폴더에 복원하지 않았다.
- 홈의 6개 탭을 세 화면 폭에서 확인했다. 320px에서 프로필 격자의 최소 폭 때문에 발생한 약 3px 가로 넘침을 수정하고 홈·목차를 다시 검사했다. 프로필의 기분 선택기는 좁은 폭에서 줄바꿈된다.
- 일반 글과 별도 구조를 가진 게시글 목록은 각각의 문서 구조에 맞춰 검사했다. 대표 홈·기사·긴 표 목차의 캡처도 눈으로 확인했다.
- 원시 결과와 캡처는 배포에서 제외한 `.jekyll-local/ui-audit/`에 있다. 자동 검사는 사용자별 글꼴·확장 프로그램·오디오 출력이나 실물 GPIO 장비의 동작을 보장하지 않는다.

## 보존·실행·배포

기존 미스테이징 삭제 파일 67개는 복원하거나 커밋하지 않았다. README와 청첩장 관련 파일은 이번 마무리 작업에서 변경하지 않았다. 개인 경로·개인 이메일 도메인·전화 형식의 추가 탐지에서는 공개 일반 글 본문의 개인 연락처가 발견되지 않았다. 병원 글의 최초 탐지는 공식 HIRA URL 식별자를 전화번호로 인식한 오탐이라 확인 후 제외했다. 이 검사는 모든 종류의 개인정보를 자동 판별하는 보증은 아니다. 과거 Git 이력은 재작성하지 않는다.

로컬 서버는 `http://localhost:4000`에서 실행한다. 종료 스크립트의 Ruby 설치 경로 확인을 시작 스크립트와 맞추고 실제 종료·재시작을 확인했다.

원격 `main`을 가져와 확인한 결과 새 원격 커밋이나 병합 충돌이 없었다. 모든 요청 작업과 위 검증을 마친 뒤 일반 push로 반영한다. 공개 배포 확인은 해당 커밋의 GitHub Actions 성공과 Pages URL의 HTTP 응답·본문으로 수행한다.
