- 우측 이미지가 참조하던 `img/SR.avif`는 HTTP 200으로 응답했고, 원본 Git blob과 내용이 일치했습니다.
- 원본 이미지는 626×626 픽셀의 정상 AVIF 파일로 디코딩됐습니다.
- 너비 설정이 HTML의 인라인 `style` 속성에 있었습니다. 페이지의 `default-src 'self'` 보안 정책은 인라인 스타일을 차단하는 조건이므로, 크기 설정을 CSS 파일로 옮겼습니다. ([MDN 설명](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/style-src))

### 변경 내용

- `img/SR.png`: 원본 AVIF를 같은 크기의 PNG로 변환해 추가했습니다.
- `_includes/rightbar.html`: PNG 경로, `relative_url`, 대체 텍스트와 이미지 크기 속성을 적용했습니다.
- `css/style.css`: `.sidebar-shrek` 클래스에 너비 100%, 최대 너비 100%, 높이 자동 설정을 추가했습니다.
- 이미지 비율을 유지하면서 우측 영역의 너비에 맞춰 표시하도록 구성했습니다.

### 검증 범위

- PNG 미리보기에서 슈렉 이미지가 정상 표시되는 것을 확인했습니다.
- 서버가 제공하는 페이지에서 PNG 경로와 새 이미지 클래스를 확인했고, 제공되는 CSS에 비율 유지 규칙이 반영된 것을 확인했습니다.
- 페이지, CSS와 PNG 이미지가 모두 HTTP 200으로 응답했습니다. PNG 응답 형식은 `image/png`였고, 원본 PNG와 빌드 결과의 파일 해시도 일치했습니다.
- 변경한 HTML·CSS 파일의 Git diff 공백 검사를 통과했습니다.
- 연결된 브라우저가 없어 브라우저 화면 캡처를 통한 레이아웃 확인은 수행하지 못했습니다.

## 2026-10-04 15:18:16 KST — Windows 로컬 서버 구동 지원

위 시각은 `start-server.ps1`과 `stop-server.ps1`의 마지막 수정 시각입니다.

### 소스 복원

- GitHub의 `origin/main`을 가져와 위 기준 커밋이 최신임을 확인했습니다.
- 체크아웃이 완료되지 않아 소스가 없던 작업 폴더에 파일을 복원했습니다.
- Windows에서 사용할 수 없는 따옴표·콜론·제어 문자가 포함된 경로 14개를 정상 파일명으로 정리했습니다.
- 변경한 경로의 파일 내용을 원본 Git blob 해시와 비교했습니다. 14개 모두 내용이 동일한 이름 변경으로 확인됐습니다.
- 원래 Git 상태와 경로 복원 자료는 `.git/codex-initial-state/`에 보관했습니다.

### 실행 환경과 의존성

- Ruby 3.3.12와 MSYS2 Devkit을 `D:\kimyongrok\tools\Ruby33-x64`에 설치했습니다.

- `Gemfile.lock`에 Windows 플랫폼 `x64-mingw-ucrt`를 추가했습니다.
- `Gemfile`의 Windows 플랫폼 조건을 `:windows`로 정리했습니다.
- 오래된 Jekyll의 Logger 초기화 오류와 Liquid의 `tainted?` 호출 오류를 해결하도록 호환 버전을 적용했습니다.
