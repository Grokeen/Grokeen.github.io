정규식 전체 일치와 입력 검증을 예제로 확인하며 정리했다.

> 2020년 학습 순서를 재구성한 공부 노트다. Java 11 기준이며 실제 근무·수강 이력을 주장하지 않는다. [실행 준비와 공통 pom.xml](/study/2020/java-spring/#run)을 먼저 확인한다.

## 오늘 정리한 개념

String.matches와 Matcher.matches는 전체 문자열 일치를 검사한다. 일부 포함 여부를 찾는 find와 목적이 다르다. 숫자 형태가 맞는지와 업무상 허용 범위인지는 따로 검증한다.

## 따라 해 보기

아래 전체를 UTF-8 Main.java로 저장한 뒤 javac --release 11 -encoding UTF-8 Main.java, java -Dfile.encoding=UTF-8 Main으로 실행한다.

{% raw %}
```java
import java.io.*;
import java.math.*;
import java.nio.charset.StandardCharsets;
import java.nio.file.*;
import java.time.*;
import java.util.*;
import java.util.stream.*;

public class Main {

  public static void main(String[] args) throws Exception {
    java.util.regex.Pattern p = java.util.regex.Pattern.compile("[A-Z]{2}-[0-9]{3}");
    System.out.println(p.matcher("AB-123").matches());
    System.out.println(p.matcher("xAB-123").matches());
  }
}
```
{% endraw %}

## 확인 결과

```text
true
false
```

## 코드를 따라 읽기

대문자 두 글자, 하이픈, 숫자 세 자리라는 형태를 정의했다. 앞에 x가 붙은 두 번째 문자열은 전체 형식에 맞지 않는다. 같은 패턴을 반복 사용하면 Pattern을 재사용할 수 있다.

## 헷갈린 부분과 주의점

정규식만으로 코드가 실제 존재하는지 확인할 수 없다. 복잡한 패턴과 긴 입력은 실행 비용도 고려한다.

## 복습 문제

find를 쓰면 두 번째 문자열에서 일치를 찾을까?

**풀이:** AB-123 부분을 찾을 수 있지만 전체 형식 검증과는 다르다.
