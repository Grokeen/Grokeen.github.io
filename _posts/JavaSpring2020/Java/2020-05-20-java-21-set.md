Set의 중복 제거와 순서을 예제로 확인하며 정리했다.

> 2020년 학습 순서를 재구성한 공부 노트다. Java 11 기준이며 실제 근무·수강 이력을 주장하지 않는다. [실행 준비와 공통 pom.xml](/study/2020/java-spring/#run)을 먼저 확인한다.

## 오늘 정리한 개념

Set은 equals 기준으로 중복 원소를 허용하지 않는다. LinkedHashSet은 처음 삽입된 순서를 유지하므로 입력 순서를 보존하며 중복을 제거하는 예제에 적합하다.

## 따라 해 보기

아래 전체를 UTF-8 Main.java로 저장한 뒤 javac --release 11 -encoding UTF-8 Main.java, java -Dfile.encoding=UTF-8 Main으로 실행한다.

{% raw %}
```java
import java.io.*;
import java.math.*;
import java.nio.charset.StandardCharsets;
import java.nio.file.*;
import java.time.*;
import java.util.*;
import java.util.stream.*;

public class Main {

  public static void main(String[] args) throws Exception {
    Set<String> unique = new LinkedHashSet<>(Arrays.asList("b", "a", "b"));
    System.out.println(unique);
    System.out.println(unique.add("a"));
  }
}
```
{% endraw %}

## 확인 결과

```text
[b, a]
false
```

## 코드를 따라 읽기

첫 b와 a는 추가되고 두 번째 b는 기존 원소와 같아 추가되지 않는다. 이미 있는 a를 add한 결과도 false다. 순서 보장 여부는 Set 인터페이스 전체가 아니라 구현의 계약이다.

## 헷갈린 부분과 주의점

TreeSet은 비교 결과를 기준으로 원소를 구분하므로 Comparator가 equals와 일관적인지 검토한다.

## 복습 문제

HashSet도 삽입 순서를 보장할까?

**풀이:** 아니다. 순서가 필요하면 그 계약을 제공하는 구현을 고른다.
