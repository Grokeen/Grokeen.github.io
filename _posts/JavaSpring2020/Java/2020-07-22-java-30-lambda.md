람다·함수형 인터페이스·메서드 참조을 예제로 확인하며 정리했다.

> 2020년 학습 순서를 재구성한 공부 노트다. Java 11 기준이며 실제 근무·수강 이력을 주장하지 않는다. [실행 준비와 공통 pom.xml](/study/2020/java-spring/#run)을 먼저 확인한다.

## 오늘 정리한 개념

람다는 추상 메서드 하나인 인터페이스의 구현을 간결하게 표현한다. Predicate는 조건, Function은 변환처럼 역할이 다르다. 캡처한 지역 변수는 final 또는 사실상 final이어야 한다.

## 따라 해 보기

아래 전체를 UTF-8 Main.java로 저장한 뒤 javac --release 11 -encoding UTF-8 Main.java, java -Dfile.encoding=UTF-8 Main으로 실행한다.

{% raw %}
```java
import java.io.*;
import java.math.*;
import java.nio.charset.StandardCharsets;
import java.nio.file.*;
import java.time.*;
import java.util.*;
import java.util.stream.*;

public class Main {

  public static void main(String[] args) throws Exception {
    java.util.function.Predicate<String> longWord = s -> s.length() >= 4;
    java.util.function.Function<String, Integer> length = String::length;
    System.out.println(longWord.test("java"));
    System.out.println(length.apply("spring"));
  }
}
```
{% endraw %}

## 확인 결과

```text
true
6
```

## 코드를 따라 읽기

test는 참·거짓을, apply는 변환값을 돌려준다. String::length는 입력 문자열의 길이를 구하는 메서드 참조다. 짧은 표현이라도 부수 효과와 예외 발생 가능성을 고려한다.

## 헷갈린 부분과 주의점

캡처한 변수의 재대입과 객체 내부 변경은 다른 문제다. 람다를 썼다고 공유 객체 접근이 안전해지는 것은 아니다.

## 복습 문제

지역 변수에 나중에 다시 값을 대입하면 캡처할 수 있을까?

**풀이:** 사실상 final 조건을 잃으므로 컴파일 오류가 난다.
