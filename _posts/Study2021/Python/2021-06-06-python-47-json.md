딕셔너리를 파일이나 통신에서 옮길 수 있는 문자열로 바꾸었다. 파이썬의 출력 표현과 JSON 문법은 같지 않았다.

> Python 3.9 기준. 코드를 `example.py`로 저장해 `python3 example.py`로 실행한다.

## 오늘 정리한 개념

json.dumps는 파이썬 객체를 JSON 문자열로, json.loads는 JSON 문자열을 파이썬 객체로 변환한다. dump와 load는 파일 객체를 대상으로 한다. JSON의 true·false·null은 각각 True·False·None으로 연결된다. ensure_ascii=False는 한글을 이스케이프 대신 그대로 표시한다.

## 따라 해 보기

{% raw %}
```python
import json

reading = {"장소": "실내", "temperature": 23, "active": True}
text = json.dumps(reading, ensure_ascii=False)
print(text)
restored = json.loads(text)
print(restored["temperature"] + 1)
print(type(restored["active"]).__name__)
```
{% endraw %}

## 실행 결과

```text
{"장소": "실내", "temperature": 23, "active": true}
24
bool
```

## 코드를 따라 읽기

dumps 결과는 문자열이고 loads 후에는 다시 딕셔너리다. 한글이 보이는 방식만 달라질 뿐 ensure_ascii 옵션이 인코딩 자체를 선택하는 것은 아니다. JSON에는 정수·실수·문자열·배열·객체 등 표현 가능한 자료형이 정해져 있어 임의의 클래스를 바로 저장할 수는 없다.

## 헷갈린 부분과 주의점

`str(딕셔너리)`는 JSON 변환이 아니다. 외부 텍스트를 eval로 읽지 않고 json.loads를 사용하며 형식과 필요한 키도 검증한다.

## 복습 문제

`json.loads("null")`의 결과는 무엇일까?

**풀이:** 파이썬의 None이다. 문자열 `"null"`을 그대로 반환하는 것이 아니다.
