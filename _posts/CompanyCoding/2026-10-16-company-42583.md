**학습 유형:** 큐·이벤트 시뮬레이션

[백준 추가 100문제](/study/2024/baekjoon/)와 별도로 정리한 기업 코딩테스트 대비 글이다. 2026년 10월 16일 공식 원문의 조건을 확인했고 아래 입력은 직접 구성했다. 특정 기업의 반복 출제 횟수나 온라인 정답 판정을 주장하지 않는다.

## 문제를 이해한 방식

트럭은 주어진 순서로 한 대씩 진입한다. 무게 한도 때문에 기다릴 때 매초 빈 작업을 반복하지 않고 가장 이른 퇴장 시각으로 시간을 이동할 수 있다.

## 풀이 순서

1. 큐에 퇴장 시각과 무게를 저장한다.
2. 새 진입 시각에 이미 나간 트럭을 제거한다.
3. 무게가 넘으면 다음 퇴장까지 기다리고 진입한다.

## 풀이가 성립하는 이유

다리 위 무게는 큐 원소의 합이다. 다음 퇴장 전까지는 무게가 줄지 않으므로 그 시각으로 건너뛰어도 가능한 더 이른 진입을 놓치지 않는다.

## Java 풀이와 실행 예제

아래 전체를 UTF-8 Main.java에 저장하고 javac --release 11 -encoding UTF-8 Main.java, java -Dfile.encoding=UTF-8 Main으로 실행한다. 별도 표준 입력 없이 main의 두 예제를 호출한다. 공식 플랫폼에 제출할 때는 imports와 Solution 클래스만 사용하고 로컬 실행용 Main은 제외한다.

{% raw %}
```java
import java.util.*;

class Solution {
public int solution(int bridge_length,int weight,int[] truck_weights){Deque<int[]> bridge=new ArrayDeque<>();int time=0,load=0;for(int w:truck_weights){time++;while(!bridge.isEmpty()&&bridge.peekFirst()[0]<=time)load-=bridge.pollFirst()[1];while(load+w>weight){time=bridge.peekFirst()[0];while(!bridge.isEmpty()&&bridge.peekFirst()[0]<=time)load-=bridge.pollFirst()[1];}bridge.addLast(new int[]{time+bridge_length,w});load+=w;}return bridge.peekLast()[0];}
}

public class Main {
  public static void main(String[] args) {
    System.out.println(new Solution().solution(2,10,new int[]{7,4,5,6}));
    System.out.println(new Solution().solution(1,10,new int[]{10,10}));
  }
}
```
{% endraw %}

## 기대 출력과 확인 관점

```text
8
3
```

main의 호출 순서대로 결과를 출력한다. 먼저 반환값을 예상한 뒤 결과와 비교하고, 아래 주의점에 해당하는 입력도 직접 바꾸어 실행해 본다. 배열 출력은 로컬 확인을 위한 표기다.

## 복잡도와 주의점

시간 O(N), 공간 O(N). 각 트럭은 한 번 들어가고 한 번 나온다.

마지막 트럭의 진입이 아니라 퇴장 시각을 반환한다. 원문의 각 트럭 무게가 한도 이하라는 조건을 사용한다.
