배열과 달리 항목 수를 늘리고 줄이는 목록을 사용했다. 목록의 Count와 내부 용량은 구분해야 했다.

> C# 12·.NET 8 콘솔 프로젝트 기준. Program.cs를 아래 코드 전체로 교체하고 `dotnet run`으로 실행한다.

## 오늘 정리한 개념

List<T>는 같은 자료형 항목을 순서대로 보관하는 가변 길이 컬렉션이다. Add로 추가하고 Remove로 같은 값의 첫 항목을 제거한다. Count는 실제 항목 수이고 Capacity는 재할당 없이 담을 수 있는 내부 용량이다. 인덱스를 쓰는 순간에는 범위 검사가 필요하다.

## 따라 해 보기

{% raw %}
```csharp
var tasks = new List<string> { "접수", "확인" };
tasks.Add("완료");
Console.WriteLine(tasks.Count);
Console.WriteLine(tasks.Remove("확인"));
Console.WriteLine(string.Join(" → ", tasks));
Console.WriteLine(tasks.Contains("확인"));
```
{% endraw %}

## 실행 결과

```text
3
True
접수 → 완료
False
```

## 코드를 따라 읽기

Remove는 항목을 찾고 제거했는지 bool로 반환한다. 제거 후 뒤 항목이 앞당겨져 순서가 유지된다. Contains는 값의 존재를 확인한다. 실제 환자 대기열에서 임의 삭제나 중복을 어떻게 처리할지는 컬렉션 선택과 별도의 업무 정책이다.

## 헷갈린 부분과 주의점

RemoveAt은 값이 아니라 위치를 받는다. 많은 항목의 첫 위치를 계속 제거하는 큐 용도라면 Queue<T>가 더 적합할 수 있다.

## 복습 문제

없는 항목을 Remove하면 항상 예외가 날까?

**풀이:** 일반적인 List<T>.Remove는 false를 반환한다. 잘못된 인덱스를 받는 RemoveAt과 다르다.
