객체를 전송 문자열로 바꾸고 다시 읽는 흐름을 정리했다. JSON 파싱 성공과 업무 데이터의 유효성은 구분했다.

> C# 12·.NET 8 콘솔 프로젝트 기준. Program.cs를 아래 코드 전체로 교체하고 `dotnet run`으로 실행한다.

## 오늘 정리한 개념

JsonSerializer.Serialize는 객체를 JSON으로, Deserialize<T>는 JSON을 지정한 자료형으로 변환한다. 반환값이 null일 수 있고 필수 항목 검증도 별도로 필요하다. record를 사용하면 데이터 구조를 짧게 드러낼 수 있다. 이 예제의 ID와 금액은 가상 데이터다.

## 따라 해 보기

{% raw %}
```csharp
using System.Text.Json;

var source = new Receipt("TEST-R01", 1200m);
string json = JsonSerializer.Serialize(source);
Console.WriteLine(json);
Receipt? restored = JsonSerializer.Deserialize<Receipt>(json);
Console.WriteLine(restored?.Id ?? "없음");

// 예제용 형식
public record Receipt(string Id, decimal Amount);
```
{% endraw %}

## 실행 결과

```text
{"Id":"TEST-R01","Amount":1200}
TEST-R01
```

## 코드를 따라 읽기

Serialize 결과는 메모리 문자열이며 실제 서버에 전송하지 않는다. Deserialize의 자료형과 속성 이름 정책을 계약에 맞춰야 한다. 금액이 음수인지, ID가 누락되었는지는 역직렬화만으로 충분히 검사되지 않는다.

## 헷갈린 부분과 주의점

필요한 속성이 없는 JSON도 기본값으로 읽힐 수 있다. 대소문자·날짜·숫자 표현 옵션을 실제 API 계약에 맞춰 확인한다.

## 복습 문제

JSON 문법이 맞으면 업무상 올바른 접수 자료일까?

**풀이:** 필수 키·상태·식별자·권한 등 의미 검증이 추가로 필요하다.
